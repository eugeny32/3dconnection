# SpaceMouse Universal Bridge — план разработки

> Модуль-посредник: читает 6DoF-данные со SpaceMouse напрямую с HID и превращает их в
> навигацию (орбита / панорама / зум) в приложениях, которые официально не поддерживаются
> драйвером 3DxWare.

**Допущение по умолчанию: Windows 10/11 + Python 3.11.** Точки замены под macOS/Linux
отмечены в разделе 4. Если целевая ОС другая — меняется только слой инъекции (§3.4).

---

## 1. Как это вообще работает

Цепочка данных:

```
USB HID ──▶ Reader ──▶ Normalizer ──▶ Mapper ──▶ Injector ──▶ Приложение
 (сырые     (парсинг   (deadzone,     (профиль   (эмуляция
  репорты)   осей)      кривые,        приложения) ввода)
                        фильтры)
```

**Ключевая идея:** большинство «неподдерживаемых» программ на самом деле умеют
навигировать — просто мышью. Blender: СКМ = орбита, Shift+СКМ = панорама, колесо = зум.
Figma: пробел+ЛКМ = панорама. Google Earth Web: ЛКМ-драг = вращение. Задача моста —
удерживать виртуальный «драг» мышью и двигать курсор пропорционально отклонению шарика
SpaceMouse. Пользователь при этом не трогает мышь вообще.

Это и есть механизм, который использует сам 3DxWare в «generic»-режиме. Мы делаем
открытый и настраиваемый аналог.

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Чтение HID | `hidapi` через `cython-hidapi` (пакет `hid`) | кроссплатформенно, не требует прав администратора на Windows |
| Ядро/цикл | Python 3.11, `asyncio` | скорость итераций; 100–200 Гц Python тянет спокойно |
| Инъекция ввода (Win) | `SendInput` через `ctypes` | без внешних зависимостей, работает в 90% приложений |
| Инъекция для игр/RawInput | ViGEmBus (вирт. геймпад) или Interception | резервный путь, фаза 5 |
| Детект активного окна | `GetForegroundWindow` + `psutil` | автопереключение профилей |
| Конфиг | TOML (`tomllib` + `tomli-w`) | читается и правится руками |
| GUI/трей | `pystray` + `PySide6` (позже) | фаза 4, до этого — CLI |
| Тесты | `pytest` + записанные дампы HID | CI без железа |

Альтернатива для продакшена: Rust (`hidapi-rs` + `enigo`) — один бинарник, задержка ниже.
Границы модулей спроектированы так, чтобы ядро можно было портировать без переписывания
логики. **Для MVP берём Python.**

### 3.1 Слой устройства

SpaceMouse — обычный USB HID. Известные VID:

* `0x046D` — старые модели под брендом Logitech (SpaceNavigator, SpaceExplorer, SpacePilot)
* `0x256F` — современные 3Dconnexion (SpaceMouse Wireless / Pro / Enterprise / Compact)

⚠️ **Не хардкодить PID из памяти.** Первая задача проекта — написать
`enumerate.py`, который перечислит все HID-устройства и покажет VID/PID/usage page.
Реальные значения берём с конкретного устройства пользователя.

Форматы репортов различаются по поколениям:

* **Старое поколение:** Report ID `0x01` = 6 байт (Tx, Ty, Tz как int16 LE),
  Report ID `0x02` = 6 байт (Rx, Ry, Rz), Report ID `0x03` = битовая маска кнопок.
* **Новое поколение:** Report ID `0x01` = 12 байт, все шесть осей сразу.

Декодер должен определять формат по длине пакета, а не по модели. Диапазон осей —
примерно ±350 или ±512 в зависимости от прошивки; калибруется на первом запуске.

### 3.2 Главная проблема: эксклюзивный захват устройства

Если установлен официальный драйвер, он держит устройство и наш ридер получит пустоту
или ошибку доступа. Варианты решения (реализовать детект + подсказку пользователю):

1. **Windows:** остановить службу `3DxService` / `3DconnexionHID`
   (`sc stop 3DxService`) или выгрузить её на время работы моста.
2. **Linux:** остановить `spacenavd` (`systemctl stop spacenavd`), либо наоборот —
   читать *из* spacenavd через libspnav и не трогать HID вовсе (более дружелюбный путь).
3. **macOS:** выгрузить `3DconnexionHelper` из автозапуска.

Модуль `device/conflict.py` должен уметь: обнаружить конфликт, назвать процесс-держатель,
предложить команду остановки (без автоматического выполнения — только с подтверждением).

### 3.3 Нормализация и фильтры

Порядок обработки каждой оси:

1. Вычитание нуля (калибровка при старте, устройство в покое 2 сек).
2. Deadzone — радиальная, не покомпонентная (иначе диагонали «залипают»).
3. Нормализация в диапазон `[-1.0, 1.0]`.
4. Экспоненциальная кривая: `out = sign(x) * |x|^gamma`, gamma по умолчанию 1.8 —
   даёт точность в малых отклонениях.
5. Опциональный **dominant axis**: подавлять оси слабее максимальной в N раз.
   Критично для новичков — иначе орбита «плывёт» при попытке панорамировать.
6. Экспоненциальное сглаживание (EMA, alpha ≈ 0.3).

### 3.4 Слой инъекции

Абстракция:

```python
class Injector(Protocol):
    def move_relative(self, dx: float, dy: float) -> None: ...
    def button(self, btn: Button, down: bool) -> None: ...
    def scroll(self, ticks: float, horizontal: bool = False) -> None: ...
    def modifier(self, key: Key, down: bool) -> None: ...
    def cursor_pos(self) -> tuple[int, int]: ...
    def set_cursor_pos(self, x: int, y: int) -> None: ...
```

**Windows:** `SendInput` с `MOUSEEVENTF_MOVE` (относительное перемещение),
`MOUSEEVENTF_MIDDLEDOWN/UP`, `MOUSEEVENTF_WHEEL`. Клавиши-модификаторы — `KEYBDEVENT`
со скан-кодами, а не VK (надёжнее в приложениях с DirectInput).

**macOS:** `CGEventCreateMouseEvent` + `CGEventPost(kCGHIDEventTap, ...)`.
Требуется разрешение Accessibility; приложение должно быть подписано.

**Linux:** `/dev/uinput` через `python-evdev` — работает и в X11, и в Wayland
(XTest под Wayland бесполезен). Нужно правило udev для доступа без root.

**Накопление субпикселей:** движение считается во float, в `SendInput` уходит целая часть,
остаток переносится в следующий тик. Без этого медленные движения просто теряются.

### 3.5 Драг-сессия — самая тонкая часть

Эмуляция «зажатой кнопки мыши» имеет жизненный цикл:

```
IDLE ──(|axis| > start_threshold)──▶ ENGAGING ──▶ ACTIVE
                                                    │
ACTIVE ──(|axis| < stop_threshold в течение 250 мс)──▶ RELEASING ──▶ IDLE
```

Обязательные детали:

* **Гистерезис** (start_threshold > stop_threshold) — иначе кнопка дребезжит.
* При входе в ACTIVE: сохранить позицию курсора, переместить курсор в центр вьюпорта
  активного окна, нажать кнопку.
* При выходе: отпустить кнопку, **вернуть курсор на исходное место**. Пользователь не
  должен замечать, что курсор куда-то ездил.
* **Смена жеста внутри сессии** (орбита → панорама) требует полного релиза и повторного
  захвата с другим модификатором — нельзя менять модификатор при зажатой кнопке.
* Если пользователь физически двигает мышь во время ACTIVE — немедленно прервать сессию.

### 3.6 Профили

```toml
[profile]
name = "Blender"
match_process = ["blender.exe"]
match_title_regex = ".*Blender.*"

[sensitivity]
orbit = 1.0
pan = 1.2
zoom = 0.8

[bindings]
orbit  = { source = ["rx", "ry"], action = "drag", button = "middle" }
pan    = { source = ["tx", "ty"], action = "drag", button = "middle", modifiers = ["shift"] }
zoom   = { source = "tz",         action = "scroll" }
roll   = { source = "rz",         action = "none" }

[axes]
invert = ["ty", "rx"]
deadzone = 0.08
gamma = 1.8
dominant_axis_ratio = 0.0   # 0 = выключено

[buttons]
1 = { action = "key", keys = ["numpad_period"] }   # fit to view
2 = { action = "toggle_profile_lock" }
```

Стартовый набор профилей: `generic_orbit`, `blender`, `figma`, `google_earth_web`,
`unity_editor`, `krita`, `chrome_generic`, `photoshop`.

## 4. Реестр рисков

| Риск | Митигация |
|---|---|
| Драйвер 3DxWare держит устройство | §3.2, детект + инструкция; на Linux — путь через spacenavd |
| Приложение использует RawInput и игнорирует SendInput (частый случай в игровых движках) | Фаза 5: ViGEmBus (виртуальный геймпад) или драйвер Interception |
| Дёрганый курсор / потеря плавности | фиксированный тик 120 Гц, накопление субпикселей, EMA |
| Жест ломается при потере фокуса окна | подписка на смену foreground-окна → форс-релиз сессии |
| Приложение в полноэкранном эксклюзивном режиме | документировать как неподдерживаемое, предлагать borderless |
| Античит блокирует синтетический ввод | явно предупредить в README: онлайн-игры не цель проекта |
| Разные DPI/масштаб дисплеев | объявить процесс DPI-aware (`SetProcessDpiAwarenessContext`), считать в физических пикселях |
| Неизвестная модель устройства | автоопределение формата по длине репорта + режим `--dump` |

**Правовой аспект:** реверс HID-протокола ради совместимости — стандартная практика,
есть открытые прецеденты (`spacenavd`, `libspnav`, драйверы в ядре Linux). Но **не**
включать в репозиторий файлы SDK или драйвера 3Dconnexion и не использовать их
торговые марки в названии продукта.

## 5. Дорожная карта

### Фаза 0 — Разведка (0.5 дня)
Перечислить HID-устройства, снять дампы репортов в покое и при отклонении по каждой оси,
задокументировать формат в `docs/protocol.md`.
**Готово когда:** есть таблица «ось → байты → диапазон» для конкретного устройства.

### Фаза 1 — Ядро чтения (1–2 дня)
Reader + decoder + filters + CLI-визуализация (шесть полосок в терминале, 60 Гц).
**Готово когда:** полоски двигаются плавно, при отпускании шарика все оси уходят в 0,
процессор загружен < 3%.

### Фаза 2 — Первая инъекция (2–3 дня)
Win32-инжектор, драг-сессия, один захардкоженный профиль (рекомендую Google Earth Web —
навигация простая, ошибки сразу видны).
**Готово когда:** можно облететь здание, ни разу не тронув мышь; курсор возвращается
на место после отпускания.

### Фаза 3 — Профили и автопереключение (2 дня)
TOML-загрузчик, матчинг по процессу/заголовку, hot-reload конфига, 5+ профилей.
**Готово когда:** Alt+Tab между Blender и браузером меняет поведение мгновенно.

### Фаза 4 — Юзабилити (2–3 дня)
Иконка в трее, мастер калибровки, экранный оверлей активного профиля, автозапуск,
логирование в файл.

### Фаза 5 — Продвинутые бэкенды (по потребности)
* **WebSocket-мост + расширение браузера** — для веб-приложений (Figma, Onshape,
  three.js-вьюеры) даёт настоящие события в канвасе вместо фейковой мыши. Сильно лучше по качеству.
* **ViGEmBus** — для приложений с RawInput.
* **Нативные плагины** — Blender (Python API), Unity Editor (C# EditorWindow),
  где это даёт прямой доступ к камере.

### Фаза 6 — Упаковка
PyInstaller onefile, инсталлятор, README с матрицей совместимости приложений.

## 6. Работа в Claude Code

### 6.1 `CLAUDE.md` в корне репозитория

```markdown
# SpaceMouse Universal Bridge

## Контекст
Мост между HID-устройством 3Dconnexion SpaceMouse и приложениями без официальной
поддержки. Реализация — Python 3.11, Windows-first.

## Железные правила
- Никаких обращений к SDK или службам 3Dconnexion. Только сырой HID.
- Слой инъекции — строго за интерфейсом Injector. Никаких вызовов win32 вне inject/win32.py.
- Любая новая логика фильтрации/маппинга должна быть покрыта тестом на записанном дампе.
- Не хардкодить PID устройств: только через конфиг device_ids.toml.
- Все величины движения — float до самого SendInput.

## Команды
- `python -m spacemouse_bridge.app.cli --dump` — сырые репорты
- `python -m spacemouse_bridge.app.cli --viz` — визуализация осей
- `python -m spacemouse_bridge.app.cli --profile blender`
- `pytest -q`

## Не делать
- Не запускать реальную инъекцию ввода в тестах — только FakeInjector.
- Не добавлять GUI-зависимости до фазы 4.
```

### 6.2 Разбиение на задачи для Claude Code

Давать по одной за раз, каждая — отдельный коммит:

1. Скелет пакета, `pyproject.toml`, `pytest`, CI-заглушка.
2. `device/enumerate.py` — перечисление HID + вывод таблицы. *Здесь остановиться и
   вручную запустить на реальном устройстве, результат вложить в контекст.*
3. `device/reader.py` + `decoders.py` по добытому формату; режим `--dump` пишет
   дамп в JSONL для будущих тестов.
4. `core/state.py`, `core/filters.py` + тесты на синтетических данных.
5. `--viz` в CLI.
6. `inject/base.py` + `inject/win32.py` + `FakeInjector` для тестов.
7. `app/manager.py` — конечный автомат драг-сессии + тесты автомата (без железа).
8. `mapping/profile.py` + загрузчик TOML + валидация.
9. `app/focus.py` + автопереключение.
10. Набор профилей + документация формата.

### 6.3 Тестирование без устройства

Ключевой приём: `--dump` пишет JSONL вида
`{"t": 0.008, "report_id": 1, "data": [0,0,12,1,...]}`. Тесты проигрывают эти файлы
через `ReplayReader`, реализующий тот же интерфейс, что и `HidReader`. Драг-сессия
тестируется через `FakeInjector`, который просто копит список вызовов — проверяем,
что последовательность нажатий/движений/отпусканий корректна.

Три обязательных фикстуры-дампа: покой, чистое вращение по одной оси, смешанный жест.

## 7. Приёмочные критерии проекта

1. Задержка от движения шарика до движения картинки < 25 мс.
2. Мост работает 8 часов без утечек памяти и без «залипшей» кнопки мыши.
3. Аварийный выход по горячей клавише, который гарантированно отпускает все
   кнопки и модификаторы (страховка от залипания).
4. Минимум 5 рабочих профилей, включая одно веб-приложение.
5. Отключение устройства и повторное подключение обрабатываются без перезапуска.
